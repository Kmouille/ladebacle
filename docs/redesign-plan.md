# La Debacle website - audit and improvement plan

## Current state

Static two-page-equivalent site (single `index.html`), plain CSS, jQuery plus one small
script, hosted on GitHub Pages under the custom domain `ladebacle.fr` (via `CNAME`). No
build step, no framework. `.htaccess` is present but has no effect on GitHub Pages (it
doesn't run Apache), so anything relying on it (WebP switching, security headers) is
currently inactive.

### SEO findings

- `<link rel="canonical" href="">` is empty - actively harmful, an empty canonical can
  confuse indexing.
- No Open Graph / Twitter Card tags - links shared on Facebook/Instagram/X show no
  preview card.
- No structured data - a band with real tour dates is exactly what `MusicGroup` /
  `MusicEvent` schema.org markup is for; without it the band is invisible to Google's
  event surfaces.
- No `sitemap.xml`, and `robots.txt` isn't pointing to one.
- `robots.txt` disallows `/images/*.svg$` for Googlebot-Image, but the actual folder is
  `img/`, not `images/` - the rule currently matches nothing.
- No `<h1>` anywhere on the page - only `<h2 class="pageseparator">` per section. Not
  broken, but weak for both SEO and accessibility.

### Dates findings

- Two hardcoded `<table>` blocks ("A venir" / "Passees") edited by hand for every show.
  Adding a date means writing a new `<tr>`; when a show passes, someone has to manually
  cut the row from one table and paste it into the other.

### Style findings

- Dead CSS left over from the template this was forked from: `.mainView`, `#slogan`,
  `#bandVideo`, `button[name=backSite]`, `.footerBaner` - none match anything in the
  current `index.html`, just noise to read through.
- Colors and spacing (`#010101`, `#FEFEFE`, `15%`/`50px` paddings) are repeated as
  literals everywhere rather than named once.
- A few small inconsistencies: `footer` is declared as a rule twice, font sizes mix
  `vh`, `rem`, and `px` with no clear system.

## Plan

### 1. Dates: CSV-driven, client-side rendered (Option 1, agreed)

- New file `dates.csv` at repo root, columns: `date,venue,city,link` (date as
  `DD/MM/YYYY`, matching what's already there).
- `index.html`'s two tables become empty `<tbody>` placeholders
  (`id="upcoming-shows"`, `id="past-shows"`), markup otherwise unchanged so the
  existing CSS keeps working untouched.
- New file `js/dates.js`: on page load, `fetch('dates.csv')`, parse it, compare each
  row's date to today, sort upcoming ascending / past descending (matching current
  order), and render both tables. Kept as its own file rather than folded into
  `mainFunctions.js`, since it's a distinct concern (data loading vs. UI toggling).
- If the upcoming list is ever empty, show a small "Aucune date pour l'instant"
  instead of an empty table.
- Editing a show going forward: open `dates.csv`, add or remove a line, commit, push.
  No script to run, no build, no CI.
- Deferred: migrating to build-time generation (a script pre-renders the HTML tables
  before publish) if the client-side SEO trade-off becomes a real problem. The CSV
  stays the single source of truth either way, so this migration is low-risk later.

### 2. SEO

- Fix canonical to the fixed `https://ladebacle.fr/`.
- Add Open Graph + Twitter Card tags (title, description, image = existing band photo
  or logo, url).
- Add a semantic (visually hidden, no visual change) `<h1>` with the band name.
- Add `MusicGroup` JSON-LD (name, genre, `sameAs` linking all social profiles)
  directly in the HTML head (static, always present).
- Add `MusicEvent` JSON-LD entries, generated by `dates.js` from the same
  `dates.csv`, for upcoming shows only. Google supports JS-injected structured data
  since it renders the page before extracting it.
- Add `sitemap.xml` (one URL, trivial for a single page) and reference it from
  `robots.txt`.
- Fix the `robots.txt` Googlebot-Image rule to match the real `img/` path (or remove
  it if nothing there actually needs excluding).

### 3. Style cleanup

- Remove the dead rules listed above.
- Introduce CSS custom properties for the repeated colors and spacing values
  (`--color-bg`, `--color-text`, a small spacing scale), so a future palette or
  spacing tweak is a one-line change instead of a find-and-replace.
- De-duplicate the repeated `footer` rule, standardize font-size units.
- No palette or layout changes - refine, don't redesign.

Confirmed against the live site (2026-09-28):

- The current "A venir" table is showing a 13/06/2026 show as upcoming, even though
  that date has already passed. Live proof of the manual two-table problem; fixed
  automatically once dates.js compares each row to today.
- Footer says "Copyright (c) 2024 La Debacle" - hardcoded year gone stale. Make it
  compute `new Date().getFullYear()` in JS instead of a literal.
- On mobile, the dates table uses `table-layout: fixed` with equal column widths, so
  longer venue/city names (e.g. "Espace Claude Ducert", "Seysses-Saves (32)") wrap to
  two lines while the date column has slack. Rebalance column widths (narrower date,
  wider venue) so rows stay single-line more often.
- (Investigated and dropped) The gap before the Contact section looked oversized at
  first glance, but checking computed layout showed it's just `.shows table`'s own
  40px margin plus the normal 50px section padding stacking up - the same spacing
  rhythm used at every section boundary on the site. Not a bug, left as-is.

## Files touched

- `index.html` - meta tags, canonical, `<h1>`, JSON-LD block, table markup becomes
  placeholders.
- `dates.csv` - new.
- `js/dates.js` - new.
- `css/style.css` - trims dead rules, adds custom properties, fixes duplicates.
- `sitemap.xml` - new.
- `robots.txt` - fixed path, sitemap reference.
- `.htaccess` - left as-is by default (inert on GitHub Pages either way); could be
  deleted instead of keeping dead config around, not required for this plan.

## Out of scope (for now)

- Build-time generation for dates (explicitly deferred).
- Any visual/layout redesign beyond cleanup.
- Multi-page structure, blog, merch, newsletter, etc. - none of that was asked for.
